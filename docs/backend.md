# خادم فرصة

تطبيق الموبايل يتصل افتراضياً بواجهة سند الحية على `https://snd.avorix.io` (`/api/jobs` و`/api/job-fields` و`/api/favorites` و`/api/my-jobs` و`/api/job-reports` و`/api/notifications`). هوية الجهاز تُحفظ في التخزين الآمن وتُرسل في `X-Device-ID`. الخادم المحلي في هذا المجلد يبقى مرجع التطوير السابق على `/v1`، ولا يُستخدم كبديل صامت إذا تعذّر الوصول للخدمة الحية.

خادم صغير بواجهة REST وSQLite دائم، مناسب لبداية حقيقية بحجم محدود على خادم واحد. التصفح وإرسال الإعلان لا يتطلبان حساباً. كل إعلان جديد يبقى **قيد المراجعة** ولا يظهر للناس حتى موافقة المشرف. لا توجد إعلانات مزروعة أو أرقام تواصل وهمية في قاعدة الإنتاج.

## تشغيل محلي

يتطلب Python 3.9 أو أحدث للتطوير. نسخة Docker تستخدم Python 3.12 وGunicorn للإنتاج.

```bash
cd server
export ADMIN_TOKEN="$(python3 -c 'import secrets; print(secrets.token_urlsafe(48))')"
export DATABASE_PATH="$PWD/data/fursa.sqlite3"
python3 app.py
```

العنوان المحلي `http://127.0.0.1:8080`. خادم `app.py` المباشر للتطوير فقط؛ يبقى على loopback افتراضياً. `DEV_HOST=0.0.0.0` متاح لتجربة جهاز فعلي ضمن شبكة موثوقة، دون كشف الخادم للإنترنت. `.env.example` مثال إعدادات، ولا يحمّل Python ملف `.env` تلقائياً. لا تضع `ADMIN_TOKEN` داخل Flutter أو Git أو أوامر محفوظة في مستودع عام.

لتشغيل نسخة الويب محلياً اضبط `ALLOWED_ORIGINS` على origin الويب الكامل، بما فيه المنفذ، مثل `http://localhost:5173`. يعمل Flutter على الهاتف دون CORS لأنه لا يرسل ترويسة Origin. لا يُسمح بـ `*`.

```bash
python3 smoke_test.py
```

الفحص يستخدم قاعدة مؤقتة ويتحقق من دورة الإعلان، منع ظهور المنتظر، التحقق من المدخلات، صلاحيات الإدارة، الحذف، البلاغات، حظر الناشر، انتهاء الصلاحية، استمرارية التخزين، CORS وحدود الطلبات وHTTP محلي فعلي. لا يختبر استضافة إنتاج أو بريداً أو اتصالاً خارجياً.

## عقد API

كل الأجوبة JSON. الخطأ: `{"error":{"code":"invalid_field","message":"رسالة عربية","field":"title"}}`. `field` اختياري. تواريخ UTC بصيغة ISO 8601. API لا يحتاج JWT أو تسجيل مستخدم.

| الطريقة والمسار | النتيجة |
| --- | --- |
| `GET /health` | `{status:"ok"}` بعد فحص قاعدة البيانات |
| `GET /v1/jobs` | `{jobs:[],total,page,pageSize}` للإعلانات المنشورة غير المنتهية فقط |
| `GET /v1/jobs/{id}` | `{job:{...}}` لفرصة منشورة؛ 404 لباقي الحالات |
| `POST /v1/jobs` | `201 {id,status:"pending",managementToken}` |
| `GET /v1/submissions/{id}` | `{job:{...},status}` باستخدام `Authorization: Bearer <managementToken>` |
| `DELETE /v1/submissions/{id}` | `{success:true,status:"withdrawn"}`؛ يحذف بيانات الإعلان ووسيلة التواصل والبلاغات المرتبطة فعلياً |
| `POST /v1/jobs/{id}/report` | `{reason:"سبب البلاغ"}` ← `201 {success:true}` |

رمز إدارة الإعلان عشوائي قوي، يُعاد مرة واحدة عند الإرسال. لا يخزن الخادم إلا SHA-256 له. على التطبيق حفظ الرمز في التخزين الآمن؛ فقدانه يمنع الإدارة الذاتية. هذا ليس حساباً ولا يثبت أن المعلن مالك رقم الهاتف. بعد الحذف تصبح قراءة الإعلان 404؛ يحذف العميل نسخته المحلية أيضاً.

جسم إنشاء إعلان:

```json
{
  "title": "مطور تطبيقات Flutter",
  "company": "اسم جهة العمل",
  "companyWebsite": "https://example.com",
  "city": "دمشق",
  "category": "تقنية",
  "workType": "دوام كامل",
  "workMode": "هجين",
  "experience": "متوسط",
  "salaryMin": 700,
  "salaryMax": 1000,
  "currency": "USD",
  "salaryPeriod": "شهري",
  "description": "وصف واضح للفرصة والمسؤوليات وظروف العمل.",
  "requirements": ["خبرة عملية في Flutter"],
  "phone": "+9639XXXXXXXX",
  "email": "",
  "expiresInDays": 30,
  "contactConsent": true
}
```

رقم المثال مقصود كقالب ويجب استبداله برقم صحيح قبل الإرسال. يلزم رقم واتساب صالح أو بريد صالح على الأقل، وموافقة صريحة على نشر وسيلة التواصل. يدعم الرقم الأرقام العربية، ويحوّل `09xxxxxxxx` السوري إلى `+9639xxxxxxxx`. أرقام دولية E.164 مقبولة أيضاً للمشغلين عن بُعد. لا يجري الخادم اتصالاً بالأرقام أو إرسال بريد أو جلب روابط يضيفها المستخدم.

`companyWebsite` رابط اختياري لموقع الجهة أو صفحتها الرسمية، افتراضه نص فارغ. يقبل HTTP وHTTPS فقط وبحد أقصى 2048 محرفاً؛ يضاف HTTPS إلى النطاق المدخل دون بروتوكول. لا يقبل بيانات تسجيل دخول أو محارف تحكم/اتجاه مخفية أو مسافات أو مضيفاً غير صالح. يظهر ضمن تفاصيل الإعلان المنشور ويفتح خارج التطبيق بعد التحقق من استمرار توفر الإعلان؛ روابط الديمو لا تُفتح. لا تُجلب معاينة الرابط من الخادم ولا يعد الرابط توثيقاً لهوية المؤسسة. عند بدء الخادم، تُرقّى حمولة SQLite القديمة إلى النسخة 2 بإضافة الحقل الفارغ مع الحفاظ على الإعلانات ورموز الإدارة وحالاتها؛ العملاء والكاش القديمان يبقيان متوافقين.

الراتب اختياري (`null`)، عدد صحيح غير سالب، والحد الأعلى لا يقل عن الأدنى. العملات `SYP` و`USD` دون تحويل تلقائي. الفترات `شهري` و`بالساعة` و`للمشروع`. وصف 20–5000 محرف، عنوان 3–100، جهة 2–100، حتى 12 متطلباً بطول 2–200. الإرسال أكبر من 24 KiB مرفوض. مدة الإعلان `expiresInDays` عدد صحيح 7 أو 14 أو 30، والافتراضي 30؛ يحسب الخادم التاريخ من ساعته. حقول مثل `id` و`status` و`createdAt` و`expiresAt` لا يقبلها إنشاء الإعلان.

حقول القراءة الإضافية: `id`, `createdAt`, `expiresAt`, `status`, `employerKey`. الأخير بصمة اتصال ثابتة يمكن استعمالها لحجب إعلانات الناشر محلياً؛ ليس هوية موثقة. حالة المالك يمكن أن تكون `pending`, `published`, `rejected`, `expired`. يظهر `rejectionReason` فقط لمالك الإعلان والإدارة. الموافقة على مشاركة التواصل تسجل في قاعدة البيانات مع تاريخها ولا تنشر حقلاً للعامة.

الفلاتر: `q`, `city`, `category`, `workType`, `workMode`, `experience`, `currency`, `salaryPeriod`, `salaryMin`, `salaryMax`, `page`, `pageSize`, `sort`. صفحة افتراضية 1 وحجم افتراضي 20 وأقصى حجم 50. الترتيب `newest` أو `salary`. عند مقارنة/ترتيب الرواتب يلزم `currency` و`salaryPeriod` معاً حتى لا نقارن راتباً شهرياً بالدولار بأجر ساعي بالليرة. حدود الراتب تعني تداخل المجالين؛ الإعلانات بلا راتب لا تطابق فلتر الراتب. البحث نصي ضمن العنوان والجهة والوصف ولا يجري بحثاً دلالياً أو تصحيحاً إملائياً.

القيم المتفق عليها:

| الحقل | القيم |
| --- | --- |
| `city` | دمشق، ريف دمشق، حلب، حمص، حماة، اللاذقية، طرطوس، إدلب، دير الزور، الرقة، الحسكة، درعا، السويداء، القنيطرة |
| `category` | تقنية، تصميم، تسويق، مبيعات، مطاعم وضيافة، حِرف ومهن، إدارة ومحاسبة، تعليم، صحة |
| `workType` | دوام كامل، دوام جزئي، عمل حر، تدريب |
| `workMode` | من المكتب، عن بُعد، هجين |
| `experience` | بدون خبرة، مبتدئ، متوسط، خبير |

## الإشراف من دون حسابات للمستخدمين

تستخدم مسارات الإدارة `Authorization: Bearer <ADMIN_TOKEN>`. لا يوجد اعتماد افتراضي، ويرفض الخادم البدء برمز أقصر من 32 محرفاً أو قيمة المثال.

| الطريقة والمسار | الوظيفة |
| --- | --- |
| `GET /v1/admin/jobs?status=pending` | قائمة المراجعة؛ تدعم الترقيم والفلاتر نفسها؛ حالات `pending/published/rejected` |
| `POST /v1/admin/jobs/{id}/approve` | جسم `{}`؛ ينشر إعلاناً منتظراً غير منتهي |
| `POST /v1/admin/jobs/{id}/reject` | جسم `{reason:"السبب"}`؛ يرفض المنتظر أو يزيل المنشور فوراً |
| `GET /v1/admin/reports` | أحدث 200 بلاغ للمراجعة البشرية |
| `POST /v1/admin/jobs/{id}/block` | جسم `{reason:"سبب الحظر"}`؛ يحظر الهاتف والبريد، ويرفض الإعلانات الحالية المطابقة ويمنع إرسال إعلانات جديدة بهما |

مثال محلي للمشرف، مع الإبقاء على السر في متغير البيئة:

```bash
curl -H "Authorization: Bearer $ADMIN_TOKEN" \
  'http://127.0.0.1:8080/v1/admin/jobs?status=pending'
curl -X POST -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H 'Content-Type: application/json' --data '{}' \
  'http://127.0.0.1:8080/v1/admin/jobs/REPLACE_ID/approve'
```

المشرف مسؤول عن التحقق من الجهة، صلاحية التواصل، المحتوى المهني، عدم طلب دفعات من المتقدمين، إزالة المحتوى المسيء والرد على البلاغات. لا توجد لوحة ويب للمشرف أو تحقق OTP أو وعد بصحة كل فرصة؛ مسارات الإدارة قابلة للاستخدام من أداة API موثوقة. الحظر مرتبط بالتواصل المعلن ويمكن التحايل عليه بتغييره، لذلك لا يغني عن المراجعة. لا تعرض شارة «موثّق» لمجرد الموافقة على النص.

## نشر فعلي بـ Docker وHTTPS

1. جهّز خادم Linux واحداً وDocker Compose، ونطاقاً حقيقياً يشير إليه، وافتح 80 و443. يبقى 8080 داخلياً.
2. انسخ `server/.env.example` إلى `server/.env`. ضع سراً عشوائياً، و`API_DOMAIN` الحقيقي، وorigins الويب المسموحة فقط. لا ترفع هذا الملف إلى Git.
3. شغّل الأوامر التالية من `server`:

```bash
docker compose up -d --build
docker compose ps
```

ملف [Compose](../server/compose.yaml) يشغّل Gunicorn بمستخدم غير root وخادم Caddy أمامه لشهادة HTTPS. SQLite في volume دائم، وليس داخل طبقة الحاوية. `TRUSTED_PROXIES` مضبوط على عنوان Caddy الوحيد في الشبكة الخاصة. إذا تعارض subnet `172.31.247.0/24` مع شبكة الخادم غيّر عناوين الخدمتين وtrusted proxy معاً. لا تثق بعناوين الإنترنت كلها؛ قيمة `X-Forwarded-For` من جهة غير موثوقة يتم تجاهلها. ثبّت صور Docker إلى digest مراجَع ضمن عملية الإصدار الفعلية.

4. تحقق من `/health` عبر HTTPS، أرسل إعلاناً تجريبياً حقيقياً، تحقق من اختفائه عن العامة قبل المراجعة ثم نشره وبلاغه وحذفه. اختبر الرحلة من iPhone وعلى شبكة سورية.
5. اربط Flutter بعنوان API الفعلي وفق [README](../README.md). لا ترسل `ADMIN_TOKEN` إلى التطبيق. لا توزع نسخة المتجر بوضع البيانات التجريبية.

حدود الطلبات مشتركة بين العمال عبر SQLite: 5 طلبات إنشاء بالساعة لكل عنوان IP، 20 بلاغاً بالساعة، 180 قراءة بالدقيقة، و30 طلب إدارة ذاتية بالدقيقة. تُحتسب الطلبات المرفوضة أيضاً؛ هذا مقصود لتقييد الإساءة. الاتصال المشترك/NAT قد يجمع عدة أشخاص، فراقب الحدود وعدّلها على قياسات حقيقية. التخزين يستخدم HMAC لعنوان IP ولا يحفظ عنوانه الخام. CORS ليس مصادقة ولا يمنع الطلبات خارج المتصفح. للإقبال الكبير يلزم قياس تحميل حقيقي وخطة انتقال لقاعدة مشتركة؛ هذا الإصدار لخادم واحد ولا يعد بقدرة تحميل غير مقاسة.

راقب health و503 ومساحة القرص، واعمل نسخاً احتياطية مشفرة بطريقة SQLite online backup حتى تشمل WAL بشكل صحيح. لا تنسخ ملف SQLite منفرداً أثناء الكتابة. اختبر استعادة نسخة احتياطية قبل الإطلاق، وحدد مدة الاحتفاظ بها. دوّر السر عند الاشتباه بتسربه؛ تدويره يعيد مفاتيح تقييد IP ولا يبطل رموز إدارة الإعلانات.

## الصلاحية والخصوصية

تنتهي الفرصة بعد 7 أو 14 أو 30 يوماً من الإرسال حسب اختيار المعلن، وتختفي تلقائياً من استعلامات العامة دون الحاجة لـ cron. شغّل التنظيف يومياً لحذف بيانات الإعلان نهائياً بعد 30 يوماً إضافياً من انتهاء صلاحيته:

```bash
docker compose exec -T api python maintenance.py
```

الحذف الذاتي يزيل الإعلان ووسيلة التواصل والبلاغات مباشرة من قاعدة العمل. قد تبقى البيانات ضمن نسخ احتياطية إلى انتهاء جدول احتفاظها. يحتفظ سجل الإدارة بمعرّف الإعلان والإجراء والتاريخ دون وسيلة التواصل، وينظفه التشغيل اليومي بعد 30 يوماً. بصمات وسائل التواصل المحظورة تبقى لمنع الإساءة إلى أن يرفع المشرف الحظر يدوياً وفق سياسة المشغل؛ اذكر ذلك في سياسة الخصوصية.

قبل الإطلاق عيّن جهة تشغيل ووسيلة دعم حقيقية، وانشر سياسة عربية تحدد البيانات العامة والخاصة، غرضها، مدة الاحتفاظ، الحذف، مكان الاستضافة ومسؤول التواصل. الرقم والبريد يصبحان عامين بعد الموافقة، ما يتيح نسخهما؛ الموافقة في نموذج النشر يجب أن توضح ذلك. لا يجمع التطبيق سيراً ذاتية أو رسائل متقدمين في هذا الخادم؛ رقم واتساب والبريد يفتحان تطبيقات الجهاز.
