# فحص جاهزية إطلاق سند — 30 سبتمبر 2026

**القرار: غير جاهز للإطلاق العام حالياً.** أُصلحت أخطاء في التطبيق والخادم المرجعي، لكن الخدمة الحية تحتاج إصلاحات وصلاحيات تشغيل غير موجودة في هذا المستودع. لم ننفّذ POST/DELETE على الإنتاج أو نشرًا أو رفعًا للمتاجر؛ قراءة التفاصيل قد تزيد عدّاد المشاهدات لدى الخدمة.

## ما يمنع الإطلاق

| الأولوية | الدليل | الإجراء المطلوب |
| --- | --- | --- |
| حرج | `GET /api/jobs` وقراءة التفاصيل يكشفان `device_id`؛ شوهد في 2/2 إعلان عام. العميل يستخدم هذه الهوية مع `/api/my-jobs` والحذف. | منع نشر الهوية، ومراجعة مصادقة المالك، واستبدال وسيلة الصلاحية المكشوفة. لم نحاول استخدام هويات المعلنين أو حذف إعلاناتهم؛ قابلية الاستغلال الكاملة لم تُختبر. |
| عالٍ | مسار فرصة غير موجودة و`/health` يعيدان 404 مع `exception/file/line/trace`. | إيقاف debug في الخدمة الحية، وإخفاء التفاصيل الداخلية، وتوفير health فعلي. |
| عالٍ | CORS الحي يعيد `*` حتى لأصل غير موثوق. | السماح بالأصول المعتمدة صراحةً مع إبقاء المصادقة مستقلة عن CORS. |
| عالٍ | ملفات الربط المنشورة تعيد 200 لكن Apple يحتوي `TEAMID` وAndroid بصمة `REPLACE_…`. | Team ID وشهادة توقيع التطبيق الصحيحة ثم فحص Universal/App Links بالنسخ الموقّعة. |
| عالٍ | لا Signing Team مهيأ في مشروع iOS، ولا إعداد توقيع إصدار Android جاهز بالمشروع. | إعدادات المطوّر ومفاتيح التوقيع الفعلية؛ لم ننشئ مفاتيح نشر أو نختَر حساباً نيابة عن المشغّل. |
| عالٍ | روابط `SUPPORT_URL` و`PRIVACY_URL` لا تحمل قيماً افتراضية. لم يُتحقق من سياسة ودعم وتشغيل مراجعة فعلي. | روابط حقيقية وإعداد الإصدار وتشغيل الإشراف والدعم، ثم اختبار رحلة نشر ومراجعة وبلاغ وحذف على staging. |
| عالٍ | بقي الموقع المنشور على شاشة البداية في جلستَي Chrome جديدتين لمدة 30 و25 ثانية؛ فشل طلب خط خارجي ولم تبدأ واجهة Flutter. | إعادة فحص الموقع بعد نشر نسخة متحققة من تحميل موارد الإقلاع. لا تثبت هذه العينة فشل الموقع على كل الشبكات، والسبب الوحيد للتوقف غير محسوم. |

الخادم في `server/` يوفّر العقد القديم `/v1`. التطبيق الافتراضي يستخدم `https://admin.jobsnad.com/api`؛ إصلاح الخادم المحلي لا يصلح الخدمة المنشورة تلقائياً. طُلِب مسار كود الخدمة الحية لاستكمال إصلاحها.

## فحص الطلبات

تم تنفيذ **18 طلب GET/OPTIONS** للـAPI الحي، وفحص إضافي لوجود حقول الهوية دون تسجيل قيمها، و**3 طلبات للموقع وملفات الربط**. [النتائج التفصيلية مع الحالة والزمن وشكل الرد فقط](launch-api-audit-2026-09-30.json).

| الطلب | النتيجة المرصودة |
| --- | --- |
| `GET /api/jobs?page=1&per_page=50` | 200؛ بنية القائمة والترقيم سليمة، مع تسريب حقل الهوية المذكور. |
| `GET /api/jobs/{publishedId}` | 200؛ نفس تسريب الهوية. |
| `GET /api/jobs/{missingId}` | 404؛ تفاصيل debug مكشوفة. |
| `GET /api/job-fields` | 200؛ 45 مجالاً في الرد. |
| `GET /api/app/maintenance` | 200. |
| `GET /api/my-jobs` بمعرّف فحص جديد / بدونه | 200 قائمة فارغة / 400. |
| `GET /api/favorites` بمعرّف فحص جديد / بدونه | 200 قائمة فارغة في الحالتين. |
| `GET /api/notifications` بمعرّف فحص جديد / بدونه | 200 قائمة فارغة / 400. |
| `GET /api/jobs` و`OPTIONS /api/favorites` من أصل الموقع وwww وأصل غير موثوق | 200 / 204؛ جميعها تسمح بـ`*`. |
| `GET /health` | 404 مع تفاصيل داخلية؛ ليس فحص صحة منشوراً. |
| الموقع وملفا `.well-known` | 200؛ ملفات الربط ما زالت قوالب. |

زمن رد الطلبات المرصود نحو **0.92–2.90 ثانية** من بيئة الفحص. هذه عينة طلبات متتابعة وليست اختبار حمل أو قياساً مضموناً لكل المستخدمين. لم تُجرَ POST/DELETE على إعلانات الإنتاج؛ دورة الكتابة الحية تظل غير مثبتة دون staging أو بيانات فحص معتمدة من المشغّل.

[سجل اختبار الموقع المنشور](deployed-web-audit-2026-09-30.json) يحفظ المسارات والحالات دون بيانات المستخدمين. حُجبت كل عمليات الكتابة في المتصفح؛ تعذّر الوصول إلى صفحة الدعم/الخصوصية بسبب توقف الإقلاع، لذلك لا ندّعي أن الروابط غائبة عن النسخة المنشورة.

## الإصلاحات

- إنهاء حالة التحديث بصورة صحيحة حتى تعمل السحبات اللاحقة؛ عدم تكرار POST تلقائياً بعد خطأ شبكة أو 5xx، وتمرير هوية الجهاز في جسم تحديث قراءة الإشعار.
- استرداد الإعلان عند ضياع رد النشر عبر تحديث كامل لإعلانات المالك حتى لو كانت المحلية فارغة. تتطلب إعادة الإرسال تحققاً وتحذيراً صريحاً؛ رد قديم لا يعيد إعلاناً سُحب أثناء التحديث، وفشل البيانات الخاصة لا يعطي نجاح تحديث وهمياً.
- إبقاء الحالات الصريحة pending/rejected خارج القائمة العامة؛ منع دخول `device_id` من الردود العامة الجديدة إلى كاش الفرص. لم يُنفّذ مسح شامل للكاش التاريخي، ولا يعالج تعديل العميل انكشاف الهوية لدى الخادم.
- عزل هوية الجهاز بحسب عنوان API وحفظها بأمان، مع منع عمليات المالك عند فشل حفظها. جلب البيانات المساندة بالتوازي بعد إظهار الفرص العامة.
- إصلاح الروابط `sanad://jobs/{id}` وتكرار فتحها، وضبط معالج `app_links` على Android وiOS طبقاً لـ[توثيق Flutter](https://docs.flutter.dev/ui/navigation/deep-linking).
- تحسين تقليل الحركة وتباين خطوات النشر بالداكن وهيدر الهاتف مع النص الكبير؛ إظهار فشل فتح التواصل؛ مرجع مشاركة iPad؛ تكيف عمود التفاصيل بالويب مع العرض والارتفاع.
- تمرير اختيار مظهر التطبيق إلى `UITabBar` الأصلي أيضاً. بقي UIKit مسؤولاً عن الشريط وLiquid Glass.
- وسم بيانات العرض صراحةً على الويب؛ دعم قائمة التنقل داخل الصفحات؛ إصلاح سجل الرجوع والتقدم وحماية المسودة؛ بدء الويب الداكن دون وميض فاتح وتحميل CanvasKit وخط Roboto الاحتياطي من نفس الموقع. بقي خط الواجهة Vazirmatn.
- استبدال توقيع Android التجريبي بإعداد release مستقل؛ غياب المفتاح يمنع بناء إصدار نشر بدل إخراج نسخة بمفتاح debug. [إعداد التوقيع الرسمي](https://docs.flutter.dev/deployment/android#sign-the-app).
- في الخادم المحلي: منع تعارض البلاغ مع الحذف، رفض `NaN/Infinity` في JSON، وتصحيح `Retry-After`.

## التحقق وحدوده

- نجح `dart format .` و`flutter analyze --no-pub` الكامل بعد آخر تعديل. نجح بناء الويب release ببيانات العرض وWasm dry run؛ لم يُختبر تشغيل إصدار Wasm منفصل.
- نجحت **124 حالة API محلية** في `server/smoke_test.py`: القراءة والإنشاء والمراجعة والرفض والصلاحيات والبلاغ والحظر والحذف والتزامن والانتهاء والاحتفاظ وCORS وحدود الطلبات وHTTP loopback فعلي.
- نجحت **27 حالة واجهة** في harness مؤقت خارج المشروع: ست شاشات بعرض 320/390، نص 200%، فاتح/داكن، تحقق حقول، تقليل حركة iOS، وفشل فتح التواصل.
- نجحت **18 حالة بيانات وتنقل** تشمل عدد محاولات الطلب، ترتيب الصفحات، حالات المراجعة، منع تسريب الهوية للكاش، تعطل التخزين الآمن، التحديث المتكرر وتعارض المالك والروابط. ونجحت **3 حالات استرداد نشر**: اكتشاف الإعلان دون POST آخر، إعادة إرسال صريحة بعد تحقق، ومنعها عند تعذر التحقق.
- نجح Chrome النهائي بعروض 320 و390 و768 و1440: الحفظ واستمراره بعد إعادة التحميل، البحث بلا نتائج، الفلاتر، الرجوع والتقدم. نجح الانتقال من الفلاتر للنشر وحماية المسودة من رجوع المتصفح على 390 و1440. حُجبت الطلبات الخارجية عمداً؛ وصل التطبيق للواجهة في نحو 2.9–3.4 ثوانٍ محلياً دون طلبات خارجية أو أخطاء JavaScript. هذا ليس قياس أداء إنتاجياً. [نتائج Chrome](launch-browser-chromium-2026-09-30.json).
- في WebKit 26.6 على macOS شوهد الإقلاع والحفظ بعد إعادة التحميل والفلاتر والرجوع والتقدم بالأحجام الأربعة، دون أخطاء JavaScript أو موارد إقلاع خارجية. بقيت فحوص إدخال النص وحماية المسودة غير محسومة: اختلف توقيت تحديث البحث، وتعذر الوصول إلى محرر Flutter من حقل semantics في الفحص المركز. لا نعلن نجاح Safari كاملاً أو وجود عطل مثبت في حماية المسودة؛ يلزم تحقق فعلي. [تفاصيل WebKit وحدود الأتمتة](launch-browser-webkit-2026-09-30.json).
- نجح بناء Android ARM64 بوضع profile وبيانات العرض؛ APK بحجم **33.1 MB** في `build/app/outputs/flutter-apk/app-profile.apk`. هذا بناء اختبار، وليس إصدار متجر موقّعًا. اختبار `:app:validateSigningRelease` توقف بالرسالة المقصودة عند غياب `android/key.properties`؛ لا يوجد fallback لتوقيع debug. المحاولة متعددة المعماريات توقفت لنفاد المساحة؛ نجحت إعادة البناء المحددة لـARM64 بعد تنظيف ملفات الفحص المؤقتة.
- نجح `flutter build ios --simulator --debug --no-pub --dart-define=API_BASE_URL=demo` بالملفات النهائية، وجرى التثبيت على محاكي iPhone 17 منفصل يعمل بـiOS 26.5. نجحت رحلة الترحيب والتبويبات الثلاثة الأصلية والتفاصيل، وفتح الرابط المخصص أثناء التشغيل وتكراره بعد إغلاق التفاصيل. نجح اختيار الداكن داخل التطبيق مع بقاء نظام iOS فاتحاً، بما فيه `UITabBar` الأصلي، ثم استعادة المظهر التلقائي. تأكد ظهور لوحة المفاتيح الأصلية؛ لم يُنفّذ اختبار إدخال عربي كامل عليها.
- أظهرت لقطة iOS النهائية تباين شريط الحالة الصحيح في التفاصيل الفاتحة. شوهد فتح التفاصيل من رابط عند تشغيل التطبيق والرجوع للرئيسية؛ لم تُحسب حالة XCTest الأخيرة ناجحة لأن شرطها بحث عن اختفاء عنوان الوظيفة الذي يظهر أيضاً في قائمة الرئيسية.

[سجل iOS التفصيلي](launch-ios-2026-09-30.json) يميّز الاختبارات الناجحة عن التحقق البصري والحالات غير المثبتة. أُغلق وحُذف محاكي الفحص المنفصل وبقي محاكي المستخدم دون تعديل. اختبارات المتصفح خدمت نسخة محلية؛ لم يُختبر إعداد إعادة كتابة المسارات في استضافة Apache الفعلية أو إعادة تحميل رابط تفاصيل مباشر عليها.

لا يوجد جهاز Android متصل أو AVD مثبت في بيئة الفحص. لا تشمل النتائج VoiceOver/TalkBack فعلياً، أو إحساس الهزات، أو تسليم واتساب والبريد على جهاز حقيقي، أو Safari على iPhone، أو حملاً إنتاجياً، أو قبول متجر. محاولة تشغيل Reduce Motion من إعدادات المحاكي لم تثبت تغيير إعداد النظام؛ التحقق الناجح لهذه الحالة هو اختبار واجهة Flutter، لا اختبار إعداد iOS الفعلي. يلزم استكمال هذه الفحوص قبل الإطلاق.

الأداء عند التوسع ما زال محدوداً: العميل يجلب حتى 40 صفحة × 50 فرصة ثم يفلتر محلياً، والويب يبني بطاقات القائمة دفعة واحدة. التحسين اللاحق يحتاج ترقيم عرض وفلاتر خادمية وقوائم تبني العناصر المرئية، مع قياس على جهاز Android اقتصادي وشبكة ضعيفة.
