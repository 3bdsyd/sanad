# بانر مشترك والإشعارات وشاشة المعلن

أُضيف بانر لشاشة الإشعارات في الموبايل عبر نفس `ScreenBanner` و`BannerAdSession` المستخدمين في تفاصيل الفرصة. الويب والديمو لا يطلبان AdMob، والقسم الفارغ من الإشعارات لا يفتح طلباً إعلانياً لمجرد دخول الصفحة.

## مصدر واحد للكاش والقرار

هوية الكاش هي **وحدة الإعلان + العرض + الاتجاه**، وليست اسم الشاشة. تستخدم الشاشتان وحدة البانر نفسها من AdConfig؛ لا يجوز نقل كائن محمّل من وحدة إلى وحدة مختلفة. اسم الموضع يبقى لتشخيص العرض، وcontextKey لتمييز فرصة عرض لاحقة، ولا يُخلطان مع الهوية الفعلية للمخزون.

- مالك واحد وAdWidget واحد للكائن. تغطية المسار بصفحة أخرى أو الخلفية أو لوحة المفاتيح تزيل العرض وتحرر الملكية، دون إلغاء طلب SDK الجاري لمجرد التنقل.
- الإعلان الصالح يعاد استخدامه بين التفاصيل والإشعارات، حتى لو اكتمل تحميله بعد مغادرة الشاشة التي طلبته. لا تُسجّل impression أو paid من إعادة الإرفاق نفسها.
- يبقى عمر 55 دقيقة وسياسة SDK للتحديث، والتجديد بسبب سياق جديد بعد impression لا يحدث قبل مرور 60 ثانية على آخر تحميل. لا مؤقت تدوير سريع بين الشاشتين.
- مفاتيح انتظار الفشل مرتبطة بوحدة البانر المشتركة أيضاً. الانتقال من التفاصيل للإشعارات لا يتجاوز No fill أو يفتح دفعة محاولات مستقلة. تغيير المقاس أو الوحدة والموافقة وانتهاء العمر يعالج مركزياً.
- ScreenBanner يجمع شرط ظهور المسار والكيبورد والخلفية وبدء المتحكم؛ لا توجد نسختان من كود التحميل داخل صفحات المنتج.

هذا يعيد استخدام المورد ويقلل التأخر والطلبات المهدورة، ولا يضمن أعلى دخل أو احتساب ظهور ثانٍ للكائن ذاته. توصية الإبقاء والتحديث البطيء من [إرشادات AdMob](https://support.google.com/admob/answer/2936217?hl=en)، وصلاحية المخزون والتحديث أثناء الظهور من [دليل البانر](https://developers.google.com/admob/ios/banner). تبقى تقارير حساب الناشر مرجع الإيراد؛ الحساب غير متاح للمالك حالياً ولم تُغير إعداداته.

## الواجهة

حذفت حشوة التواصل السفلية الإضافية، مع إبقاء مساحة مؤشر النظام عبر SafeArea. احتُفظ بالفصل بين الإعلان والمحتوى والأزرار. عنوان التفاصيل يحتفظ بعرض متساوٍ للتحكمين الجانبيين، فيتوسط فعلياً قبل التمرير وبعد ظهور عنوان الوظيفة المختصر.

شاشة «إعلاناتك» تعرض العنوان وبنهاية السطر كبسولة «أضف فرصة عمل» مع أيقونة زائد. أزيلت مقدمة التعليمات والكارد الكبير وزر التحديث داخل القسم وفي شريطه العلوي؛ السحب للتحديث باقٍ. عند تكبير الخط تصطف الإجراءات في سطر تالٍ لعدم قطع النص أو تصغير مساحة اللمس. لم يُستبدل UITabBar الأصلي.

## الويب

أكد المالك عدم وجود موافقة أو كود AdSense. [خطة إعلانات الويب](web-ads-plan-2026-11-03.md) تشرح اختيار المنتج وتجهيز صفحات عامة يمكن تقييم محتواها وخطوات التفعيل بعد الموافقة. لا تُستعمل حزمة H5 الخاصة بالألعاب أو كود AdMob كبديل. لم تُفعل إعلانات ويب أو يُنشر هذا الإصدار ضمن هذه المهمة، ولا توجد تعديلات API مطلوبة لهذه الإعلانات.

## التحقق

نجحت 135 حالة Flutter وflutter analyze. جرى التنقل بين شاشات التفاصيل والإشعارات الفعلية ودفع مسار تفاصيل آخر ثم الرجوع: بقي نفس AdWidget المحمّل وطلب SDK واحد، مع إزالة عرض المسار المغطى. اختُبر No fill أثناء تغيير اسم الشاشة وعدم تجاوز مهلة الانتظار، والأقسام الفارغة والممتلئة، ومركز العنوان في الوضعين العادي والمختصر، وحذف الكارد والتحديث وموضع زر الإضافة وتكبير النص. راجعت صور واجهة حقيقية بالخط المحلي بعرض 390 و320 وخط 200%، والتفاصيل الداكنة مع مساحة نظام مماثلة للآيفون. الاختبارات تستعمل قناة SDK وهمية ولا تثبت نسبة دخل إنتاجية.

نجحت أبنية Web Release وAndroid Debug arm64 وiPhone Release التجريبي 1.0.0 (11). جرى فحص توقيع الحساب المجاني Team 5XWVXZ43MV وملف TTL=7 والشهادة قبل تثبيت تحديث «سند تجربة» على آيفون عبدالرحمن؛ أكد devicectl البناء 11 ونجاح التشغيل. بقي تطبيق المتجر وتوقيعه دون تغيير، واستُعملت وحدات Google الاختبارية في النسخة الشخصية. الحزمة المحلية `build/review/web-release-20261103e` تتضمن 317 ملفاً ببصمات مطابقة للبناء والأرشيف؛ لم تُرفع على الاستضافة. `dart format .` عدّل ملفات مراجعة مؤقتة فقط، ومرّ فحص المسافات دون أخطاء.
