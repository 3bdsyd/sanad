## نتائج الطلبات الستة عشر

| الطلب | النتيجة الحية |
| --- | --- |
| `GET /job-fields` | 200؛ 45 مجالاً. |
| `POST /jobs` | 201؛ أُنشئ إعلان مؤقت، ثم ظهر في قائمة إعلانات معرّف الاختبار. |
| `POST /jobs/{id}` | 200؛ عُدّل عنوان الإعلان المؤقت وتأكدت القيمة الجديدة بالقراءة. |
| `GET /my-jobs` | 200؛ قائمة فارغة أولاً، ثم الإعلان المؤقت، ثم فارغة بعد حذفه. |
| `DELETE /jobs/{id}` | 200؛ حُذف الإعلان المؤقت فقط. لم يُستخدم المعرّف الثابت `1` الموجود في المجموعة. |
| `GET /jobs?page=…&per_page=50` | الصفحات 1–5 أعادت 200؛ جُمعت 201 فرصة. |
| `GET /jobs/{id}` | 200 لمعرّف منشور صالح. المعرّف `2` في المجموعة غير موجود وأعاد 404. |
| `GET /filterjob?...` | 200. استعلام المجموعة الذي يرسل `country=داخل` لا يطابق بيانات الخدمة ويعيد صفراً؛ الاستعلام بـ`country=سوريا&state=حمص` أعاد 11 فرصة. |
| `GET /favorites` | 200؛ فارغة في البداية وبعد إزالة مفضلة الاختبار. |
| `POST /favorites` | أضاف الإعلان بـ201 و`is_added:true`، ثم أزاله بـ200 و`is_added:false`. أُرسل جسم الطلب بمفتاحي `device_id` و`job_id`. |
| `POST /job-reports` | 201؛ أُرسل بلاغ على الإعلان المؤقت فقط. |
| `GET /notifications` | 200؛ قائمة فارغة لجهاز الاختبار. |
| `POST /notifications/2/read` | 404 لمعرّف إشعار غير موجود على جهاز الاختبار؛ رفض متوقع لهذا المعرّف. |
| `POST /app/visit` | 200؛ قُبل جسم الزيارة ومعرّف الاختبار. |
| `GET /app/maintenance` | 200؛ استجابة الصيانة قابلة للقراءة. |
| `GET /app/version-check` | 200 على iOS وAndroid. مع `version=1.3.0` لا يلزم تحديث قسري؛ مع إصدار التطبيق المحلي `1.0.0` يعلن الخادم تحديثاً قسرياً لأن الحد الأدنى لديه `1.2`. `platform=web` يعيد 422 لأن الخادم لا يقبل هذه المنصة. |

الاستجابات الخاطئة المقصودة للاختبار هي إذن 404 للفرصة/الإشعار غير الموجودين، و422 لمنصة غير مدعومة. معرّف العينة `2` ومرشح `country=داخل` لا يصلحان كبيانات نجاح. استجابة 404 للتفاصيل تكشف حقول debug (`exception`, `file`, `line`, `trace`)؛ هذه مشكلة في الخدمة المنشورة. كما أن رسالة `/app/version-check` الواردة عند فحص إصدار `1.0.0` مشوّهة نصياً. فحص الإصدار وتحرير الإعلان اختُبرا عبر API لكنهما غير مربوطين بتدفق واجهة حالية في التطبيق.

سجّل التدقيق الحي السابق أيضاً ظهور `device_id` في تفاصيل الإعلان العام. ينبغي لمشغّل الخدمة إزالة هوية المالك من الردود العامة وإيقاف تفاصيل debug قبل اعتبار API آمناً للإطلاق؛ كود الخدمة المنشورة ليس ضمن هذا المستودع.

## التحقق من تطبيق الويب

شُغّلت نسخة إنتاج الويب المبنية محلياً على Chrome نظيف وبعرض هاتف، واتصلت بالخدمة الحية. ظهرت أول لقطة Flutter بعد نحو 70 مللي ثانية من بدء التنقل في هذا الفحص؛ هذا قياس لهذه البيئة المحلية وليس ضماناً لزمن كل شبكة أو جهاز. وصلت طلبات الكتالوج والبيانات المساندة بنجاح، دون أخطاء JavaScript أو فشل CORS.

- جلب التطبيق صفحات `/jobs` الخمس وعرض 201 فرصة.
- بحث «تنظيف» أظهر 18 نتيجة محلية؛ أعاد مسار الخدمة 17، ويشرح قسم تدقيق البيانات سبب الفرق.
- مرشح «بدون خبرة» أرسل القيمة المتوافقة `experience=غير مطلوبة` وجلب الصفحات السبع؛ عرض 131 نتيجة. قبل التصحيح كانت الواجهة ترسل تسمية لا تستخدمها بيانات الخدمة.
- اختُبرت إضافة مفضلة وإزالتها من البطاقة؛ أرسل المتصفح `device_id` و`job_id` الصحيحين، واستجابت الخدمة 201 ثم 200.
- اختُبر التمرير عبر القائمة. أصبح بناء البطاقات كسولاً باستخدام `SliverList.builder`، بدلاً من إنشاء كل بطاقات النتائج مسبقاً؛ اجتازت سلسلة إيماءات التمرير الخمس في Chrome خلال 961 مللي ثانية. هذا تحقق تفاعلي، وليس قياساً لمعدل الإطارات.

تحسين الإقلاع يتيح للويب رسم أول إطار دون انتظار فك صورة الشعار، ويبدأ تهيئة بيانات الجهاز الآمنة بالتوازي مع جلب القائمة العامة. تظل العمليات الخاصة منتظرة تهيئة الهوية قبل الإرسال. أبقيت شاشة الإقلاع الأصلية على iOS وAndroid.

## تعديلات توافق بيانات الخدمة

- يضيف طلب الفلترة `country=سوريا`، المتوافق مع الفرص الحالية؛ كانت قيمة المثال `داخل` سبب استجابة فارغة.
- يحوّل فلتر العمل من المكتب إلى قيمة الخادم `work_type=في المقر`، ومرشح «بدون خبرة» إلى `experience=غير مطلوبة`.
- تُنظّف المسافات الزائدة من قيم الحقول القادمة من الخدمة وتُوحّد صيغ العمل الحضوري وفترات الراتب: «شهرياً» ← «شهري»، و«أسبوعياً» ← «أسبوعي»، و«يومياً» ← «يومي». يرسل فلتر الخدمة الصيغ التي تتوقعها بياناتها، بينما تطابق الواجهة الصيغ الموحّدة على كامل الكتالوج.
- قيمتا العمل عن بعد والخبرة قد تعيدان صفراً عندما لا توجد سجلات مطابقة في بيانات الخدمة الحالية. هذا لا يعني تعطل الطلب.

## تدقيق بيانات الكتالوج

أُعيد جلب السجلات الـ201 وفُحصت حقول العنوان والجهة والمحافظة والبلد ونوع الدوام وطريقة العمل والخبرة وتاريخ الإنشاء. لم تكن هذه الحقول فارغة في أي سجل، وكانت المعرّفات الـ201 فريدة. توجد فرصة واحدة بمحافظة «غير محدد». قُرئت حقول المجال والراتب ووسيلة التواصل المتداخلة أيضاً من استجابتها المتداخلة.

بعض حقول المحتوى ليست مصنّفة بقيم موحدة: لدى 47 فرصة 22 وصفاً حراً مختلفاً للخبرة، كما يحتوي حقل فترة الراتب على أوصاف إعلانية بجانب الفترات القياسية. يحتفظ التطبيق بالنص الأصلي لهذه الأوصاف؛ لذلك لا تندرج كلها ضمن خيارات الفترات «شهري/أسبوعي/يومي/بالساعة/للمشروع». جرى توحيد صيغ الشهر والأسبوع واليوم الشائعة حتى لا تسقط من المطابقة أو ترتيب الراتب.

في إعادة فحص البحث الحية، أعاد `/filterjob` سبع عشرة نتيجة لـ«تنظيف»، بينما تطابق البحث المحلي في كامل الكتالوج ثماني عشرة فرصة؛ الإضافة المحلية تطابق كلمة البحث في المتطلبات، التي لا يعيدها مسار بحث الخادم ضمن نتائجه. أُبقي التطابق المحلي لأنه فرصة ذات صلة، ولا يعني اختلاف العدد أن أحد الطلبين فشل. أعاد استعلام البحث الذي لا يطابق شيئاً صفراً كما هو متوقع.

تحقق البناء والتحليل والاختبارات بعد هذه التغييرات: `flutter analyze --no-pub` و`flutter test --no-pub` و`flutter build web --no-pub` نجحت. يركّز سجل الاختبارات المحلية على تحليل الاستجابات وتكوين الاستعلامات دون كتابة بيانات على الخدمة.

## إعادة اختبار نموذج الويب

أُعيد بناء نسخة الويب بعد تحديث نصوص النموذج، ثم اختُبرت في Chrome:

- أُرسل إعلان اصطناعي واحد من النموذج الفعلي، وقبلته الخدمة بـ201. وصل ردّ الإعلان بحقول الراتب وجهة التواصل والمجال متداخلة؛ قرأها التطبيق وعرض شاشة استلام الإعلان. تضمّن الجسم راتباً أسبوعياً بعملة USD، ونوع عمل عن بُعد، وخبرة مطلوبة، ومحافظة دمشق، ومدة 14 يوماً. استُخدمت جهة اتصال نطاقها `.invalid` وبيانات اختبار فقط.
- رُصدت استجابة 201 ومعرّف الإعلان 223. انتهت محاولة السحب اللاحقة من صفحة «المتابعة» بمهلة انتظار؛ لم يصل رد يؤكد نجاح الحذف أو فشله. لا ينبغي اعتبار هذا الإعلان محذوفاً حتى يُتحقق من قائمة المالك بعد عودة الخدمة.
- في البناء النهائي، أظهرت صفحة الإعلان التسمية «متطلبات الخبرة» وشرحت قيمة الخبرة المطلوبة بوضوح. تعرض حقول الراتب فترة الدفع، مثل «أسبوعياً»، عند وجود مبلغ.
- اختُبرت حالات رفض النموذج في الواجهة: غياب وسيلة التواصل، وبريد إلكتروني غير صالح، وإرسال نموذج صحيح من دون الموافقة. ظهرت رسائل التحقق بالفصحى، ولم يُرسل أي `POST /jobs` في هذه الحالات.

أُعيد فحص `GET /app/maintenance` بعد الاختبارات، لكن اتصال TLS انتهى بمهلة انتظار (`HTTP 000`). لذلك تظل حالة الإعلان 223 غير مؤكدة، ولا يمكن التحقق من وجوده أو إتمام سحبه إلى أن تستجيب الخدمة.

بعد آخر تعديل نجح `flutter analyze --no-pub` و`flutter test --no-pub` (15 اختباراً) و`flutter build web --no-pub`.
