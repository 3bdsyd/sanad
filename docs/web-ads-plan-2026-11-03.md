# إعلانات الويب لسند — القرار والتنفيذ المطلوب

أكد المالك أن jobsnad.com ليس لديه بعد موافقة AdSense أو كود وحدة ويب. **لا توجد إعلانات ويب مفعّلة في هذا التحديث**، ولا يُعاد استعمال معرّف AdMob كأنه كود AdSense. لا تغيير للباك أو شروط نشر الفرص بسبب إعلانات الهاتف الجديدة.

## اختيار المنتج

- `google_mobile_ads` في المشروع مخصص لـiOS وAndroid، ولا يدعم تشغيل AdMob في المتصفح: [الدليل الرسمي](https://developers.google.com/admob/flutter/quick-start).
- خيار الموقع المعتاد هو **AdSense للمحتوى** بعد قبول الموقع، أو Google Ad Manager عند وجود إعداد مناسب ومصادر طلب وإدارة تشغيلية. إضافة Ad Manager وحدها لا توفر طلباً إعلانياً أو تضمن دخلاً أعلى.
- الحزمة الرسمية `google_adsense 0.1.2` المنشورة من labs.flutter.dev تقول إنها مخصصة للألعاب، وإن Ad Unit Widget تجريبي وبالدعوة وغير متاح للتقديم حالياً. سند ليس لعبة؛ لذلك لم تُثبت هذه الحزمة ولم تُستخدم H5 Games Ads كحيلة: [صفحة الحزمة](https://pub.dev/packages/google_adsense).

## ما يلزم في موقعنا قبل التقديم

الموقع الحالي Flutter يرسم الفرص والتفاصيل داخل المحرك؛ HTML الابتدائي في web/index.html يحتوي محمّل التطبيق، وليس قائمة فرص أو نص تفاصيل قابلاً للقراءة مستقلاً عنه. وجود meta description أو نصوص مخفية للحساب الآلي لا يعوّض محتوى المستخدم الحقيقي. Google قد توقف الإعلانات على محتوى لا تستطيع تقييمه: [سياسة المواضع](https://support.google.com/adsense/answer/1346295?hl=en#ads-on-content-that-we-cannot-evaluate).

التوصية المعمارية لسند هي جعل صفحات الفرص العامة والتفاصيل HTML قابلة للقراءة والفهرسة، عبر SSR/SSG أو صفحات عامة محسّنة تدريجياً، مع بقاء تطبيق الموبايل مستقلاً. هذه توصية لتجهيز المحتوى، وليست ادعاء أن Google تمنع جميع مواقع Flutter أو أن HTML يضمن الموافقة. لا يُستبدل الموقع الحالي تلقائياً ضمن تعديل واجهة الهاتف.

الصفحات المطلوبة: نتائج عامة بترقيم صفحات وروابط فعلية، و`/jobs/{id}` بعنوان الفرصة والجهة والبلد والمحافظة والوصف والشروط والتواريخ والحالة. ترسم فقط حقول الجمهور من API بعد تنقيتها؛ لا device_id ولا مفاتيح إدارة أو بيانات حالة pending/rejected. الصفحات غير المتاحة تعرض حالتها الصحيحة دون إعلان على صفحة خطأ فارغة. تبقى سياسة الخصوصية والدعم وروابط التنقل قابلة للوصول.

بعد تجهيز المحتوى، يضيف صاحب حساب AdSense jobsnad.com إلى Sites ويستكمل إثبات الملكية وطلب المراجعة. لا تتطلب هذه الخطوة إرسال كلمة مرور للمطور، وقد تستغرق الموافقة وقتاً: [إضافة الموقع ومراجعته](https://support.google.com/adsense/answer/12169212?hl=en).

## دمج الإعلانات بعد الموافقة

1. تسليم معرّف AdSense الفعلي `ca-pub-…` وكود وحدة المحتوى `data-ad-slot` من الحساب المقبول، مع تأكيد أن الموقع Ready. لا تُشتق صلاحية AdSense من معرّفات ca-app-pub الحالية.
2. تحميل سكربت AdSense الرسمي مرة واحدة في الصفحة العامة، وإضافة وحدة responsive داخل تدفق المحتوى بعد عدد مناسب من الفرص أو فقرة التفاصيل، مع حجز حجمها ومنع تراكبها مع البحث أو التواصل أو التنقل.
3. إضافة **ads.txt** بجذر الموقع بالنص الذي يقدمه الحساب. ملف app-ads.txt الحالي يخص تطبيقات الموبايل ولا يحل محل ملف الويب.
4. إعداد تجربة الموافقة الخاصة بالويب من حساب الناشر وفق متطلبات Google والمناطق التي يخدمها الموقع؛ موافقة UMP في تطبيق الهاتف ليست موافقة المتصفح تلقائياً.
5. دعم الانتقال بين الصفحات وفق سياق المحتوى وزيارة المستخدم. لا إعادة تحميل للوحدة بسبب Flutter rebuild أو بحث متأخر أو مؤقت في الخلفية. لا نسخ DOM إعلان قديم بين صفحتين أو تخزين صورته لإعادة احتساب عرضه. سياسة AdSense تختلف عن التحديث التلقائي لبانر AdMob: [منع التحديث غير المطلوب](https://support.google.com/adsense/answer/1346295?hl=en#auto-refreshing-ads).
6. فحص المقاسات والهاتف ولوحة المفاتيح والـno fill وحاجب الإعلانات، وعدم تغطية أي إجراء أو فرض مشاهدة قبل الوصول للمحتوى. تراجع تقارير الحساب بعد وجود زيارات حقيقية، دون وعد بنسبة ربح قبل القياس.

الوحدات المبدئية المقترحة في صفحات الفرص والتفاصيل العامة فقط. لا إعلان جديد في شاشة نشر فرصة أو حالة فارغة لمجرد زيادة requests. لا طلب إعلانات إنتاجية آلياً خلال فحوص الواجهة، ولا ضغط على إعلان صاحب الحساب.

## حدود التسليم الحالي

تعديلات الموبايل تستخدم BannerAdSession وScreenBanner مشتركين للتفاصيل والإشعارات. لا يمكن مشاركة كائن إعلان الهاتف أو كاشه مع المتصفح؛ لكل منتج SDK وسياسة وعمر مستقل. لا حاجة لإنشاء جدول إعلانات في الباك لهذه التعديلات. تجهيز صفحات HTML العامة ومسار تقديم AdSense ما زالا عمل ويب مستقلاً يسبق تفعيل كود إعلان حقيقي؛ لم يُنفذ تغيير معماري أو نشر غير مطلوب بصمت.
